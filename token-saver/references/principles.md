# 12 עקרונות חיסכון בטוקנים

הרעיון שמתחת לכולם: בכל תור נשלחת כל ההיסטוריה מחדש. קונטקסט הוא לא זיכרון חינם, הוא החשבון.

## רמה 1: הרגלים לכולם (כולל claude.ai באפליקציה)

## 1. תפתחו שיחה חדשה לכל נושא
- **מה:** פותחים שיחה נקייה לכל משימה שלא קשורה לקודמת.
- **למה:** שיחה ארוכה גורמת לכל שאלה קטנה לעלות כמו כל ההיסטוריה שקדמה לה.
- **איך:** ב-Claude Code `/clear` בין נושאים (`/rename` ואז `/resume` כדי לחזור). ב-claude.ai פותחים צ'אט חדש.

## 2. אל תדביקו קבצים שלמים, תפנו למקום המדויק
- **מה:** מפנים לקובץ ולשורות המדויקות במקום להדביק מסמכים, לוגים ומסכים שלמים.
- **למה:** כל מה שמדביקים נכנס לחלון ונשלח מחדש בכל תור. הפניה מדויקת קוראת מעט.
- **איך:** "תוסיף ולידציה לפונקציית login בקובץ auth.ts" במקום להדביק את הקובץ. PDF ממירים לטקסט קודם.

## 3. בחרו את המודל הנכון למשימה
- **מה:** מודל יקר רק ל-20% הקשים; מודל זול לשאר.
- **למה:** פייבל/Opus עולים כמה מונים לתור מ-Sonnet, ו-Sonnet יותר מ-Haiku. השארת מודל יקר כברירת מחדל היא אחת הסיבות הגדולות להפתעות בחשבון.
- **איך:** `/model` להחלפה, ברירת מחדל ב-`/config`. פייבל/Opus לארכיטקטורה ובאגים קשים, Sonnet לשוטף, Haiku לפעולות פשוטות. ב-claude.ai בורר המודל.

## 4. תשתמשו ב-Projects במקום להדביק את אותו רקע (claude.ai)
- **מה:** ידע קבוע של פרויקט נשמר פעם אחת ולא מודבק מחדש בכל שיחה.
- **למה:** מסמכים ב-Project נשמרים במטמון ומשומשים מחדש בכל צ'אט בפרויקט; רק חלקים חדשים נספרים.
- **איך:** מכניסים מסמכי עבודה מרכזיים ל-Project, הוראות פרויקט קצרות, ועובדים בפרויקט נפרד לכל נושא. המקבילה ב-Claude Code היא סקילים.

## 5. תורידו את רמת המאמץ (effort) כשלא צריך
- **מה:** מורידים את רמת המאמץ למשימות פשוטות.
- **למה:** טוקני חשיבה מחויבים כטוקני פלט. בפייבל 5 אי אפשר לכבות חשיבה, אז effort הוא המנוף היחיד. הנתון הרשמי: medium חסך 76% מטוקני הפלט כמעט בלי לרדת בציון.
- **איך:** `/effort` (רמות low, medium, high, xhigh, max; `/effort auto` לברירת המחדל של המודל). ב-claude.ai יש בורר effort.

## רמה 2: היגיינת Claude Code

## 6. תדעו לאן הולכים הטוקנים
- **מה:** מודדים לפני שמתקנים.
- **למה:** אי אפשר לחתוך את מה שלא רואים. `/context` מראה מה ממלא את החלון, `/usage` מראה כמה מכסה נשארה.
- **איך:** `/context` לרשת (`/context all` לפירוט לפי פריט ורמזי אופטימיזציה). `/usage` (כינויים `/cost`, `/stats`; `d`/`w` ל-24 שעות מול 7 ימים).

## 7. תשמרו על CLAUDE.md רזה
- **מה:** שומרים את CLAUDE.md קצר.
- **למה:** הקובץ נטען במלואו בתחילת כל סשן ואף פעם לא מפונה. כל שורה עולה טוקנים לאורך כל הסשן, וקובץ ארוך גם פוגע בציות להוראות.
- **איך:** יעד מתחת ל-200 שורות. נהלים ארוכים עוברים לסקילים (נטענים רק כשצריך). הערות HTML `<!-- -->` נחתכות (חינם). `.claude/rules/` לטעינה רק עם קבצים תואמים. `/doctor` מציע קיצוצים.

## 8. תכבו שרתי MCP שלא בשימוש
- **מה:** מכבים שרתי MCP שלא בשימוש.
- **למה:** כל שרת מחובר דוחף רשימת כלים וסכמות ל-system prompt, גם בלי שימוש. זה מס סמוי גדול על החלון.
- **איך:** `/mcp` לראות ולכבות שרתים, או `claude mcp disable <name>`. טעינת סכמות נדחית כברירת מחדל (ToolSearch); כלי CLI (gh, aws) לא עולים רשימת כלים כלל.

## 9. תריצו /compact ממוקד בהפסקות, ו-/rewind על כיוון שגוי
- **מה:** דוחסים בהפסקות טבעיות עם הנחיה, ומבטלים כיוון שגוי.
- **למה:** `/compact` מחליף את השיחה בסיכום מובנה, כך שכל תור שולח הרבה פחות. דחיסה ממוקדת עדיפה על אוטומטית באמצע משימה. `/rewind` קורא prefix שכבר במטמון (זול).
- **איך:** `/compact focus on the auth bug` לפני משימה חדשה. `/rewind` (או Escape כפול) לחזור לנקודת ביקורת; Escape לעצור את קלוד ברגע שהוא סוטה.

## 10. תבקשו תוכנית לפני כל עבודה גדולה (plan mode)
- **מה:** תכנון בקריאה בלבד לפני עריכות.
- **למה:** תיקון חוזר (rework) הוא מה ששורף הכי הרבה טוקנים במשימות גדולות. תוכנית קצרה מונעת סבבי תיקון. זה ההחזר הכי גדול על ההשקעה.
- **איך:** Shift+Tab לכניסה ל-plan mode במשימות מורכבות. שקול `opusplan`: Opus מתכנן, Sonnet מבצע.

## רמה 3: מתקדמים

## 11. תנו למודל החזק לנהל: תתי-סוכני Opus מבצעים, פייבל מנצח
- **מה:** מבקשים מפייבל 5 (או המודל החזק שזמין) לבצע משימה בתור מנהל: הוא מתכנן, מחלק עבודה ומבקר; תתי-סוכנים מסוג Opus מבצעים בפועל; סוכן שנתקל בבעיה מעלה אותה חזרה למנהל להכרעה.
- **למה:** הפלט המפורט (טסטים, לוגים, קריאת קבצים) נשאר בקונטקסט של תת-הסוכן; רק סיכום קצר חוזר לשיחה הראשית. ההסלמה למעלה מונעת מעובד זול להסתבך לבד ולשרוף טוקנים על ניסיונות. אזהרה: multi-agent בלי שליטה צורך בערך פי 15 טוקנים משיחה רגילה - להתאים את גודל הכוח למשימה.
- **איך:** פרומפט מוכן: "תבצע את המשימה הבאה: [המשימה]. אתה המנהל: תפעיל תתי-סוכנים מסוג Opus שיבצעו את העבודה עצמה. אם סוכן נתקל בבעיה או בהחלטה לא ברורה, הוא מחזיר אותה אליך ואתה מכריע." למשימות פשוטות עוד יותר: `model: haiku` או `sonnet` ב-frontmatter של תת-הסוכן.

## 12. אל תחליפו מודל באמצע סשן, ותשמרו סשנים קצרים
- **מה:** שומרים על המטמון חם וסשנים קצרים.
- **למה:** קריאה מהמטמון עולה כ-10% ממחיר input רגיל (כ-90% הנחה). החלפת מודל/effort, הדלקת fast mode או שינוי MCP באמצע סשן מבטלים את המטמון ומכריחים קריאה מלאה מחדש.
- **איך:** בוחרים מודל ו-effort בתחילת סשן ולא נוגעים. סשנים קצרים עם קובץ מסירה (handoff). ניטור עם ccusage/claude-monitor (ר' monitoring.md). ל-API: batch (חצי מחיר) ו-prompt caching.

## שלושה מיתוסים לנפץ
- **"fast mode חוסך":** לא. הוא מהיר ויקר, מושך מקרדיטים בתשלום מהטוקן הראשון. `/fast` הוא Opus בלבד.
- **"אחליף מודל וזה יאפס את המכסה":** לא. המכסה (חלון מתגלגל 5 שעות ותקרה שבועית) משותפת בין claude.ai, Claude Code ו-Cowork, ובין כל המודלים. החלפת מודל רק עוקפת הודעת "הגעת לתקרת Opus".
- **"effort נמוך = מודל טיפש":** לא. הנתון הרשמי: medium חסך 76% מטוקני הפלט כמעט בלי לרדת בציון.
